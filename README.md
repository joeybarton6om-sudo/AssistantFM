# Assistant FM

## Installation Windows

L'ancien installateur `distribution\AssistantFM-Installation.exe` est un prototype. La version restaurée depuis `distribution\AssistantFM-Beta-2026-11-10-NSIS-dossiers.exe` s'installe pour l'utilisateur courant dans `%LOCALAPPDATA%\Programs\Assistant FM` par défaut, sans droits administrateur. Elle nécessite Windows et Microsoft Edge WebView2 Runtime. L'installateur n'est pas signé : Windows SmartScreen peut afficher un avertissement. La page de configuration des dossiers a été vérifiée ; l'installation complète reste à tester sur un autre PC avant diffusion.

L'en-tête de l'application propose un lien vers le [Discord communautaire Assistant FM](https://discord.gg/YR2e8kMHeF). Le lien ouvre le navigateur et rejoindre le serveur reste facultatif.

Dans la bêta NSIS, les dossiers de logos, visages et sauvegardes peuvent être choisis pendant l'installation ; ceux trouvés dans l'emplacement habituel de Football Manager sont proposés. Les trois champs sont facultatifs. Des réglages déjà enregistrés dans l'application restent prioritaires et ne sont pas écrasés par l'installation : modifiez-les dans l'application si nécessaire. Des liens vers [TCM Logos](https://www.tcmlogos.com/fr/tcm27-logos-fm27/) et le [DF11 Facepack](https://www.tcmlogos.com/fr/df11-facepack/) figurent dans les réglages. Les raccourcis sur le bureau et dans le menu Démarrer sont optionnels et décochés par défaut. La désinstallation conserve les données personnelles.

Après reconstruction et réinstallation, les raccourcis créés utilisent explicitement le fichier `assistantfm.ico` installé avec l'application ; les raccourcis déjà présents ne sont pas modifiés tant que l'installateur n'est pas relancé.

Dans l'application, ouvrez « Dossiers Football Manager » dans le panneau latéral pour modifier les chemins ; redémarrez ensuite l'application. « Ouvrir le dossier des sauvegardes » ouvre le dossier configuré dans l'Explorateur ; le sélecteur de fichiers de l'application ne s'y positionne pas automatiquement.

Dans la version navigateur, « Dossiers Football Manager » affiche également les liens vers les packs et le remerciement à TCMLogos ; le choix des dossiers depuis l'interface reste réservé à la version installée.

Les sauvegardes et données extraites restent sur votre ordinateur. L'application installée utilise `%LOCALAPPDATA%\AssistantFM` pour sa configuration, ses données extraites et son profil WebView. Le suivi et les autres données du navigateur de la version locale ne sont pas automatiquement transférés dans la fenêtre installée : utilisez les fonctions d'export et d'import des données personnelles de l'application si vous souhaitez les récupérer.

L'exécutable embarque le code, mais ne le chiffre pas de manière inviolable : une personne disposant du programme peut l'extraire ou l'analyser. Les données locales ne sont pas chiffrées par cette distribution. Avant une diffusion publique, vérifiez les licences des composants tiers et les droits d'utilisation des marques, données et ressources Football Manager ; les packs personnels de logos et de visages ne sont pas inclus.

## Utilisation depuis les sources

Lancez `Lancer Assistant FM.bat`, puis utilisez le site local ouvert à l'adresse indiquée par le serveur et sélectionnez une sauvegarde à extraire ou un fichier `players_data.json` existant. N'ouvrez pas `index.html` directement avec `file://` : les API locales nécessaires aux logos, visages et noms de compétitions ne sont alors pas accessibles.

### Overlay compact à côté du jeu

`Lancer Overlay.bat` (ou `AssistantFM.exe --overlay`) ouvre une petite fenêtre toujours au premier plan : budget, masse salariale, contrats qui expirent, jeunes à suivre, valeurs les plus élevées et cibles du suivi. Choisissez une sauvegarde `.fm` ou `.fmf` avec le bouton prévu, puis laissez l'extraction automatique suivre les modifications du fichier pendant votre partie. Le raccourci `Ctrl+Alt+F` affiche ou masque la fenêtre, y compris lorsque Football Manager a le focus. Le suivi local est partagé avec la fenêtre principale, et « Assistant FM complet » ouvre l'interface complète dans une autre fenêtre.

Pour activer une licence, utilisez également le serveur local ou l'application installée, et non le fichier HTML ouvert directement. Après une mise à jour des sources, redémarrez le serveur ; la version installée doit être reconstruite et réinstallée pour intégrer les changements.

La signature du code est vérifiée à l'activation. Dans le navigateur, la liaison est enregistrée localement dans ce profil de navigateur : elle ne permet pas de contrôler l'utilisation sur d'autres ordinateurs. La version installée utilise l'API native lorsqu'elle est disponible ; aucun de ces mécanismes locaux ne garantit une limitation centralisée à une seule machine.

## Accès gratuit et soutien

La version gratuite donne accès à « Recrutement » > « Joueurs » et « Staff technique ». Les autres vues affichent l’écran d’accès, avec un lien vers [PayPal.Me](https://paypal.me/AssistantFM). Un don vérifié manuellement par l’éditeur donne un code signé lié à l’adresse e-mail du donateur, valable un an. Il est envoyé par e-mail après vérification ; il peut ensuite être validé hors ligne dans l’application. La bannière de soutien n’utilise pas de régie publicitaire et disparaît après activation.

Lorsque l’accès complet est actif, un indicateur affiche le temps restant, arrondi à l’unité supérieure (jours, heures ou minutes), ainsi que la date et l’heure locales d’expiration. Il est actualisé au moins chaque minute tant que l’application est ouverte et devient orange pendant les sept derniers jours. À l’expiration, l’application revient à la version gratuite et propose la saisie d’un nouveau code ; les données personnelles ne sont pas supprimées.

### Préparer l’émission des codes (éditeur)

Installez les dépendances du projet, puis créez une seule fois les clés d’activation :

```powershell
python -m pip install -r requirements-desktop.txt
python gestion_licences.py init-key
```

La clé privée est chiffrée avec une phrase secrète et enregistrée dans `%LOCALAPPDATA%\AssistantFM\activation-private.pem` ; elle et sa phrase secrète ne doivent jamais être distribuées. Sauvegardez-les de façon sécurisée : les codes émis dépendent de cette clé. La clé publique `activation_public.pem` est créée à la racine du projet ; elle doit être incluse dans les distributions produites après son initialisation.

Pour Gmail, activez la [validation en deux étapes](https://myaccount.google.com/security), puis créez un [mot de passe d’application Google](https://myaccount.google.com/apppasswords). Le serveur est `smtp.gmail.com`, le port `587` (STARTTLS), et l’identifiant est l’adresse Gmail complète. N’utilisez pas le mot de passe normal du compte. Testez la connexion sans envoyer de message :

```powershell
python gestion_licences.py tester-smtp
```

Le programme demande les paramètres dans le terminal et saisit le mot de passe d’application de façon masquée ; il ne l’enregistre pas. Pour `smtp.gmail.com`, il utilise la méthode d’authentification LOGIN. Vous pouvez aussi définir `ASSISTANT_FM_SMTP_HOST`, `ASSISTANT_FM_SMTP_PORT`, `ASSISTANT_FM_SMTP_USER`, `ASSISTANT_FM_SMTP_PASSWORD` et `ASSISTANT_FM_SMTP_FROM` dans l’environnement avant de lancer les commandes.

Si l’authentification est interrompue, `python gestion_licences.py tester-smtp --diagnostic-plain` ou `python gestion_licences.py tester-smtp --diagnostic-login` teste une seule méthode d’authentification et indique le code SMTP d’un éventuel refus sans afficher les identifiants. Ces tests n’envoient pas d’e-mail.

Après avoir vérifié un don dans PayPal, envoyez le code au donateur :

**Outil graphique privé :** ouvrez `construction-editeur\dist\AssistantFM-Envoi-Licences.exe`, saisissez l'adresse du donateur, le mot de passe d'application Gmail et la phrase secrète de la clé privée. L'adresse Gmail d'envoi est préremplie avec `assistantfm27@gmail.com` et reste modifiable. Cochez la vérification du don puis confirmez l'envoi. Les mots de passe sont masqués, conservés uniquement dans la fenêtre pendant son utilisation et ne sont pas enregistrés. La clé privée doit rester disponible sur votre ordinateur à son emplacement habituel. Cet outil est réservé à l'éditeur : ne le joignez pas à l'installateur destiné aux utilisateurs.

Après acceptation du code par le serveur SMTP, l'outil graphique envoie un e-mail séparé à `assistantfm27@gmail.com` avec l'adresse du donateur et la date d'expiration, sans le code. L'acceptation par SMTP ne garantit pas la réception. Si cette confirmation échoue, l'outil avertit que le code a déjà été accepté : ne le renvoyez pas uniquement pour cette raison. La commande en terminal ne génère pas cet e-mail de confirmation.

### Bêta fermée : préparation et participation

La bêta vise d'abord 5 à 10 volontaires. L'accès complet est gratuit pendant exactement 14 jours à compter de l'émission du code individuel, sans don. Il revient ensuite à la version gratuite ; les données personnelles ne sont pas supprimées. Les inscriptions sont manuelles : aucune adresse n'est collectée automatiquement.

**Avant d'inviter les testeurs :** vérifier les licences et droits des composants et ressources, puis tester l'installation, le lancement, l'activation, l'expiration et la désinstallation sur un Windows de test vierge. La version NSIS a été testée localement mais pas sur un Windows vierge ; elle n'est pas signée. Si une version non signée est distribuée après vérification, prévenez les testeurs de l'avertissement Windows.

Pour reconstruire la bêta NSIS, utilisez `construire_beta_nsis.ps1` avec les chemins de Python et du dossier NSIS. Le script inclut la clé publique existante et les notices de licences, jamais la clé privée. NSIS et son mode de compression zlib permettent les applications commerciales sous les conditions de leur licence ; vérifiez séparément les droits des autres composants et ressources.

**Inscription et envoi (éditeur) :**
1. Recrutez des volontaires sur le [Discord communautaire](https://discord.gg/YR2e8kMHeF). Demandez-leur de vous contacter en privé ou d'écrire à `assistantfm27@gmail.com` ; ne demandez pas leur adresse e-mail dans un salon public.
2. Après inscription et disponibilité d'une version vérifiée, convenez individuellement de la remise du programme. Ouvrez l'outil graphique privé et choisissez **Bêta gratuite : 14 jours**. Saisissez l'adresse du volontaire, les identifiants d'envoi et la phrase secrète, puis contrôlez le type, la durée et le destinataire dans la confirmation avant l'envoi. La case PayPal n'est pas nécessaire pour une bêta ; elle reste obligatoire pour un code annuel. Le changement de mode décoche cette case.
3. La confirmation séparée à l'éditeur et les précautions en cas d'échec SMTP restent identiques. Ne distribuez jamais l'outil privé, la clé privée ou les mots de passe. Ne publiez pas les codes. Gardez les adresses uniquement pour organiser la bêta et limitez leur conservation au nécessaire.

**Parcours conseillé aux testeurs :**
1. Vérifiez les prérequis Windows et WebView2, puis sauvegardez vos fichiers et sauvegardes Football Manager avant de commencer. Utilisez de préférence une copie de votre sauvegarde et ne partagez pas vos données personnelles.
2. Installez uniquement le paquet communiqué par l'éditeur après les vérifications, ouvrez l'application, puis activez votre code avec l'adresse à laquelle il a été envoyé. Vérifiez le compteur de temps restant et l'accès aux différentes rubriques.
3. Essayez le recrutement joueurs et staff, l'ouverture ou l'extraction d'une copie de sauvegarde, les autres fonctions déverrouillées, les réglages de dossiers et la navigation. Notez également les difficultés d'installation et les performances.
4. Dans le forum `bugs-forum` du Discord, créez un sujet par problème avec la version de l'application et de Windows, les étapes, le résultat attendu, le résultat observé et, si utile, une capture anonymisée. Dans `suggestions-forum`, créez un sujet par idée et expliquez votre besoin et la solution souhaitée. Ne publiez ni adresse e-mail, ni code, ni mot de passe, ni sauvegarde ou capture contenant des données personnelles.
5. Faites un bilan : installation facile ou non, fonctions utiles, problèmes bloquants, suggestions prioritaires et appréciation générale. Vérifiez également le retour à l'accès gratuit après expiration.

### Envoi annuel en ligne de commande

En cas d'erreur ou de coupure pendant l'envoi, vérifiez les messages envoyés avant de réessayer : un message peut avoir été accepté même si la confirmation a été perdue. L'outil ne vérifie pas lui-même le paiement.

Vous pouvez également utiliser le terminal :

```powershell
python gestion_licences.py envoyer --email donateur@example.com
```

L’application locale n’effectue pas la vérification du paiement : le code ne doit être émis qu’après contrôle manuel du don. La licence est une protection légère, pas un DRM inviolable ; le code de l’application est présent sur l’ordinateur de l’utilisateur.

Lors d'une extraction depuis une sauvegarde, la barre indique le pourcentage d'envoi, puis le chargement progressif du résultat avec l'étape réelle en cours et les secondes écoulées. Le résultat est analysé au fur et à mesure de sa réception afin de limiter l'usage mémoire pour les grandes sauvegardes. L'extracteur ne fournit pas de pourcentage de progression global : la durée des étapes est variable. Une seule extraction à la fois est autorisée. Redémarrez le serveur après une mise à jour pour activer le suivi des étapes.

Si un build de FM27 utilise un layout tactique encore inconnu de `fmsave`, l'extraction conserve les autres données et signale l'indisponibilité des tactiques ou compositions concernées dans « Mon club » > « Tactique » ; elles seront lisibles après la prise en charge du build par une version ultérieure de l'extracteur.

Si une sauvegarde FM27 contient des listes de sponsors que `fmsave` ne peut pas valider, l'extraction conserve les autres données et signale que les données financières sont indisponibles dans « Mon club » > « Club ». Les valeurs financières ne sont pas estimées ni remplacées par des zéros.

Les fiches joueur et staff possèdent un onglet « Carrière ». Cliquer sur le nom dans le bandeau d’une fiche copie ce nom dans le presse-papiers. Les autres noms cliquables de joueurs ou de membres du staff ouvrent leur propre fiche, même depuis celle d’une autre personne. Dans la fiche d’un joueur, le comparateur d’attributs propose par défaut le meilleur joueur évaluable de l’effectif au poste et rôle sélectionnés ; la liste permet de choisir un autre joueur de l’effectif. Survolez le nom d’un attribut pour en voir l’explication. Les portraits et logos de clubs, nations et compétitions sont agrandis dans les vues de l’application. Pour les joueurs, le bandeau affiche la taille connue et le poids lorsqu’il est disponible ; la version actuelle de `fmsave` extrait la taille, mais pas le poids. L’onglet carrière présente séparément les statistiques de la saison actuelle et les saisons archivées disponibles, par club et type de compétition, sans les additionner. L'année des archives est indicative et celles-ci peuvent être incomplètes ou absentes même lorsque la saison actuelle est disponible ; les champs FM27 restent à vérifier dans le jeu. Les anciennes bases doivent être réextraites pour obtenir la saison actuelle. L'historique des postes du staff n'est pas exposé par la version actuelle de fmsave et ne peut donc pas être affiché.

## Recherche de joueurs

Au démarrage, l'application ouvre « Recrutement » > « Joueurs » ; le chargement d'une base conserve la vue en cours. Dans « Recrutement », choisissez « Joueurs », « Staff technique » ou « Similaires ». La liste des joueurs regroupe la recherche et les critères de recrutement, dont l'écart de réputation, le budget estimé et le salaire actuel maximal. Le planificateur et les bonnes affaires restent dans cette section.

Après chargement, « Mon club » > « Vue d'ensemble » propose des raccourcis vers les principales actions. Le bouton d'export produit une synthèse texte de l'effectif et des contrats proches de leur échéance, avec la date de sauvegarde et les limites des données ; elle peut être imprimée depuis un éditeur de texte.
Les onglets déroulants « Effectif », « Tactique » et « Club » permettent de choisir les vues de Mon club ; « Rechercher » et « Planifier » regroupent celles du recrutement. Dans la vue d'ensemble, dépliez « Consulter tous les contrats » pour voir les joueurs et le staff, y compris les dates manquantes ou passées.
Dans l'effectif, cliquez sur un en-tête pour trier les joueurs ; un second clic inverse le sens. Le salaire affiché est le salaire hebdomadaire actuel exporté. Les valeurs numériques manquantes restent en fin de liste et le tri CA/PA est désactivé en mode découverte.

« Recruter par poste » permet de choisir une tactique enregistrée et une place sur le terrain, puis son rôle. La référence peut être le meilleur joueur évaluable du club à ce poste, un titulaire ou une doublure attribués par le planificateur, ou un joueur du club choisi manuellement. Ces affectations sont indicatives et non les titulaires connus en jeu. Les références sont temporaires : elles disparaissent au rechargement de la base ou au changement de profil.

Le mode « Meilleur immédiatement » affiche tous les joueurs externes dont la note de rôle dépasse strictement celle de la référence. Si aucun joueur du club n'est associé au poste, les profils évaluables sont présentés sans comparaison. Les deux notes utilisent le même rôle et les mêmes poids personnalisés : seuls les profils disposant de tous les attributs pondérés et de l'aptitude au poste, chacun entre 1 et 20, sont comparés ; le nombre de candidats incomplets ou invalides exclus est indiqué. L'explication détaille les écarts d'attributs et d'aptitude. Une fiche ouverte depuis cet écran reprend le poste et le rôle de la place sélectionnée. Le mode « Futurs talents » classe par défaut les joueurs de 21 ans au plus selon leur PA global connu ; il permet aussi de trier par note actuelle, CA, marge PA − CA, âge ou coût, et de filtrer par PA et marge minimum. Le PA n'est ni une garantie de progression ni une prévision de note de rôle. Ce mode, les colonnes et tris CA/PA sont masqués en mode découverte.

La liste est paginée et les filtres se combinent : âge maximal, budget, contrat, coût connu ou inconnu. La fin de contrat couvre les 12 mois suivant la date de sauvegarde, bornes incluses ; une date absente, invalide ou antérieure est exclue. Le budget exclut les coûts inconnus. Le coût indicatif est nul pour un agent libre, sinon correspond à une clause de sortie connue ou à la valeur marchande multipliée par 1,5. Le budget initial des analyses provient de la sauvegarde ; certaines vues proposent leur propre budget. Une clause peut être soumise à des conditions : ni ce coût ni la valeur marchande ne sont le prix demandé, et l'intérêt réel du joueur n'est pas connu. Cliquez sur un nom pour ouvrir sa fiche et l'ajouter au suivi.

Dans « Joueurs », ouvrez les filtres pour combiner âge, poste, pied préféré, nationalité UE, CA, PA, contrat, valeur marchande, salaire actuel (minimum et maximum) et attributs actuels. Les pastilles permettent de retirer les critères individuellement ou de tout réinitialiser. Le filtre UE tient compte de la nationalité principale et des secondes nationalités exportées ; il ne déduit pas de citoyenneté depuis le lieu de naissance. L'écart de réputation limite les joueurs externes par rapport à la réputation du club ; la limite de coût estimé est facultative. Le salaire affiché et filtré est le salaire **actuel** exporté, pas les exigences du joueur ; les salaires ou coûts inconnus sont exclus lorsque leur limite est activée. Les bornes sont inclusives et tous les critères renseignés doivent être satisfaits. Les potentiels individuels ne sont pas exportés.

Les tableaux de recherche affichent aussi le poste en abréviation française, le drapeau et le nom de la nationalité principale, le logo du club, la compétition associée au club, la taille et le pied préféré lorsqu'ils sont exportés. Les logos proviennent des packs graphiques locaux. La compétition et le classement sont établis à partir des données disponibles et peuvent correspondre à une coupe ; les champs absents restent vides. Une réextraction est nécessaire pour obtenir la taille et les secondes nationalités dans les anciennes bases JSON.

Cliquez sur le nom ou le logo d'une compétition dans une fiche, ou sur son nom dans les résultats joueurs et staff, pour ouvrir sa fiche (accès complet, comme les fiches club). Elle présente séparément les tables de la sauvegarde, avec les rangs, matchs joués, buts marqués et encaissés et points des équipes retrouvées ; cliquez sur un club pour ouvrir sa fiche. Une réextraction avec la version à jour est nécessaire pour les buts et les statistiques individuelles. Les onglets buteurs, passeurs et notes affichent un classement **indicatif** des statistiques de championnat de la saison pour les équipes retrouvées dans toutes les tables de la fiche. Ces lignes ne sont pas rattachées à une compétition précise : elles ne représentent pas les statistiques de coupe, et les transferts ou changements de division peuvent fausser le résultat. Des équipes et joueurs peuvent manquer ; les lignes d'un joueur ayant joué pour plusieurs équipes ne sont pas additionnées. Les notes comprennent les joueurs ayant au moins un match noté, sans seuil supplémentaire ; une note sur peu de matchs peut être trompeuse. Les champs FM27 ne sont pas confirmés par l'extracteur et doivent être vérifiés dans le jeu. Les noms des phases ne sont pas disponibles. Une nouvelle extraction enregistre l'identifiant de chaque table. Pour les anciennes extractions, l'application tente de les distinguer selon leur taille : cette séparation reste indicative et, si elle est ambiguë, les équipes sont présentées par ordre alphabétique sans classement global. Les noms de compétition issus des corrections locales ne sont pas certifiés.

« Similaires » est accessible depuis « Recrutement ». Le diagnostic, les performances, le laboratoire tactique, l'optimiseur et le développement des jeunes sont regroupés dans « Mon club ». Les alertes et la comparaison sont dans « Suivi ».

Le « Mode découverte » du panneau latéral masque les valeurs CA et PA, désactive leurs filtres et exclut le CA du score de recrutement. Les captures et variations de CA sont masquées sans être écrasées. Le mode agit sur l'affichage, pas sur le fichier JSON : les attributs cachés autres que le CA et le PA restent visibles.

Dans « Mon club » > « Performances », le total de saison est affiché par défaut lorsqu'il est disponible, avec un filtre de minutes et des taux par 90 minutes. Les autres types et équipes restent consultables séparément ; « Tous les types » affiche volontairement plusieurs lignes par joueur sans les additionner. Une réextraction est nécessaire pour les anciennes bases. Ces chiffres sont **expérimentaux pour FM27** : leurs champs ne sont pas confirmés par l'extracteur et doivent être comparés au jeu. Ils ne servent pas à classer les recommandations.

## Suivi et recrutement

- Dans une fiche joueur, utilisez « Ajouter au suivi », puis l'onglet « Suivi & comparaison » pour saisir des notes et comparer de deux à quatre joueurs au poste et rôle choisis. Le score de rôle est indicatif, calculé sur les attributs disponibles et la maîtrise du poste, et non une note officielle du jeu.
- Depuis le suivi, ouvrez le planificateur ou le copilote mercato. Les cibles suivies évaluables au poste y sont proposées même si elles ne figurent pas dans les suggestions automatiques ; leur présence n'indique ni un intérêt réel ni un coût abordable.
- La fiche joueur regroupe pays, club, division et contrat dans l’en-tête. L’onglet « Profil » sépare les attributs de joueur de champ et de gardien ; l’onglet « Analyse de recrutement » rassemble l’analyse. Les aptitudes aux postes figurent sur un mini-terrain : vert 18–20, turquoise 15–17, jaune 10–14, rouge 1–9 et gris pour une note absente. Cliquez sur un poste évaluable pour sélectionner son analyse de rôle ; les chiffres sont des aptitudes aux postes, pas des notes de rôle.
- La fiche d'un membre du staff affiche les attributs effectivement exportés. Dans la version actuelle de l'extracteur FM27, seule l'adaptabilité est connue ; les autres compétences métier ne sont pas déduites du CA et restent indisponibles.
- Dans une fiche joueur, « Personnaliser les poids de ce rôle » permet de pondérer chacun de ses attributs de 0 à 5. Les poids sont propres au club et à la partie sélectionnée ; ils affectent les évaluations utilisant ce rôle dans l'application. Les attributs manquants sont exclus du calcul.
- La fiche explique les points forts et faibles relatifs aux attributs du rôle et les écarts avec le meilleur joueur évaluable de votre effectif au poste choisi. « Chercher des profils similaires » classe les joueurs capables d'occuper ce poste selon la proximité des attributs actuels du rôle. Les profils incomplets sont exclus ; les filtres « plus jeune » et « valeur marchande inférieure » nécessitent des données connues.
- Dans « Mon club » > « Diagnostic », l'analyse reprend la tactique sélectionnée et affiche la profondeur indicative et les meilleurs joueurs. Dépliez « Candidats à examiner » par poste pour consulter les profils selon le budget d'analyse et la marge de réputation de « Joueurs ». « Chercher pour ce poste » ouvre la recherche spécialisée avec la tactique, la place et une copie du budget d'analyse ; son budget est indépendant et la marge de réputation ne s'y applique pas. Depuis un résultat comparable, « Comparer et suivre » ouvre la comparaison avec la référence.
- Chaque diagnostic poste/rôle permet d'enregistrer une fiche de besoin : priorité, profil libre, budget indicatif et cibles choisies dans le suivi. Elle est propre au poste et au rôle, et ne modifie pas les filtres de recherche. Les cibles retirées du suivi restent dans la fiche jusqu'à leur retrait explicite ou la suppression de la fiche.
- Dans le laboratoire tactique et le copilote mercato, « Scénarios enregistrés » permet de nommer, réappliquer ou supprimer des simulations. Les scénarios du laboratoire conservent les postes, rôles et titulaires manuels ; ceux du mercato conservent les cibles et hypothèses de montants. Ils nécessitent un nom de partie et un identifiant stable du club et des joueurs concernés, et sont inclus dans l'export des données personnelles. Une tactique, une place ou un joueur devenu introuvable bloque la réapplication au lieu de choisir silencieusement un remplaçant. Ces simulations ne modifient pas FM.
- « Suivi » > « Historique de partie » propose une courbe et un tableau des attributs observés. Elle nécessite des captures à des dates distinctes : une valeur manquante interrompt la ligne et aucune progression future n'est prédite.
- Le « Planificateur d'effectif » attribue les titulaires et doublures sans réutiliser un joueur. Choisissez une tactique dans « Mon club » > « Tactique », puis cliquez sur une place du terrain pour consulter les deux joueurs affectés ; « Tous les postes » affiche l'ensemble. Il cherche d'abord à couvrir les titulaires, puis les doublures en réaffectant les titulaires si nécessaire. La section « Simuler des arrivées et des départs » permet de tester des départs et des arrivées depuis le suivi, sans modifier la sauvegarde ; le scénario est temporaire et disparaît au prochain chargement de base.
- Dans « Joueurs », donnez un nom aux filtres puis enregistrez-les. Les nouvelles recherches mémorisent aussi la marge de réputation, les limites de coût et de salaire et le multiple d'offre fixe de 1,5 ; les anciennes alertes conservent leurs critères d'origine. Lorsqu'une ancienne recherche utilisant un autre multiple est réappliquée, la liste utilise 1,5 et un message le signale. « Alertes » permet de les réappliquer ou supprimer, montre les nouveaux profils correspondants entre deux chargements, les variations de CA de l'effectif et les contrats expirant dans les six mois à partir de la date de jeu.

Suivi, notes, filtres et captures d'alertes restent dans le stockage local du navigateur, par club et par adresse du site. Ils peuvent être perdus si les données du navigateur sont effacées et ne sont pas automatiquement transférés entre navigateurs, ports ou ordinateurs. Sans nom de partie, deux carrières avec le même club partagent ces données. Les correspondances de joueurs absentes ou ambiguës ne sont pas devinées. Les prix demandés et la volonté de signer ne sont pas connus ; les coûts affichés sont des estimations et les clauses doivent être vérifiées dans le jeu.

Dans le panneau latéral, « Données personnelles et partie » permet d'exporter puis d'importer les suivis, notes, recherches, alertes, historiques et poids de rôles. L'import vérifie le format et demande confirmation avant de remplacer des entrées existantes. Un nom de partie choisi manuellement isole ces données pour cette partie ; laisser le nom vide retrouve les données historiques par club. Choisissez un nom différent pour chaque carrière et rechargez la base après changement pour reconstruire les alertes. Le nom n'est pas détecté automatiquement depuis la sauvegarde et les anciennes données ne sont pas copiées automatiquement.

## Directeur sportif

- **Optimiseur tactique** : dans « Mon club », l'application propose et classe six formations types et les tactiques enregistrées ayant 11 postes reconnus. Elle cherche une affectation optimale des titulaires, sans doublons, d'abord pour couvrir le plus de places puis pour maximiser la somme de leurs notes de rôle. Les doublures sont ensuite affectées sans réutiliser les titulaires ; la couverture des doublures départage les formations à égalité. Les rôles sont choisis individuellement parmi ceux disponibles dans l'application, sans évaluer leur équilibre collectif ; vous pouvez en imposer un pour une place. Sans titulaire évaluable, le premier rôle disponible sert de point de départ modifiable. L'aptitude minimale au poste est réglable à 10, 15 ou 18 ; les aptitudes et attributs nécessaires absents ou hors de 1–20 sont exclus. Les poids personnalisés sont respectés. Les identifiants absents ou dupliqués sont exclus. Cette sélection temporaire est réinitialisée au changement de base ou de profil et ne modifie pas FM.
- Le tableau de l'optimiseur classe les besoins par titulaire manquant, doublure manquante, puis note du titulaire. Cliquez sur une place pour afficher les critères du rôle et rechercher jusqu'à cinq joueurs externes mieux notés que le titulaire affecté, ou des profils évaluables si la place est vide. Un budget facultatif s'applique par joueur et exclut les coûts inconnus. Le coût et les clauses sont indicatifs ; le prix demandé, le salaire demandé et l'intérêt réel ne sont pas connus. Les fiches s'ouvrent au poste et rôle proposés.
- **Copilote mercato** : suivez les trois étapes : choisir la tactique, la priorité et le profil, examiner les besoins et sélectionner des cibles, puis vérifier les montants et comparer. Les postes manquant d'un titulaire ou d'une doublure sont signalés et classés selon la priorité choisie. Les cartes présentent les joueurs affectés sans doublon et trois candidats maximum, leur score de rôle, leurs attributs forts et faibles et leur écart avec le titulaire affecté. Le profil jeune retient les joueurs de 21 ans ou moins, sans prédire leur développement ; le profil petit budget utilise uniquement les coûts estimables dans le budget saisi. Les candidats ne sont pas filtrés par intérêt réel ou réputation. Les frais initiaux proposés sont des estimations modifiables ; renseignez aussi les salaires, ventes et économies hypothétiques pour calculer les soldes. Les montants manquants empêchent le calcul correspondant. Une même cible ne peut pas être comptée deux fois. Le bouton « Comparer ce scénario » conserve jusqu'à trois résumés temporaires côte à côte.
- **Laboratoire tactique** : dans « Mon club », partez d'une tactique enregistrée et modifiez le poste ou le rôle directement sur chaque place du terrain. Les titulaires, doublures et candidats indicatifs apparaissent au même endroit. C'est une simulation temporaire : elle ne modifie ni la sauvegarde ni la tactique utilisée dans les autres vues. Les rôles ne sont pas nécessairement ceux employés en jeu et le moteur de match n'est pas simulé.
- **Mon club** présente l’effectif dans « Effectif », sous forme de tableau filtrable par équipe, catégorie et poste, avec statuts en pastilles et terrain tactique latéral. « Tactique » contient « Ma tactique », le laboratoire et l’optimiseur ; « Club » contient la vue d’ensemble, les transferts et la confiance des données. Le diagnostic, les performances et le développement des jeunes restent accessibles depuis « Effectif ». Les filtres d’équipe utilisent l’affectation exportée ; à défaut, ils ne montrent que les joueurs des sélections tactiques. Le terrain différencie DCG/DCD par le côté et, quand les données sont disponibles, le pied fort. L’historique des mouvements et les transferts futurs/en cours ne sont pas encore fournis par l’extracteur ; l’onglet le signale sans déduire de mouvements des contrats ou des prêts.
- **Laboratoire tactique** : sélectionnez une place sur le terrain pour modifier son poste, son rôle et son titulaire. Un choix manuel est conservé dans cette simulation temporaire, sans réutiliser le joueur ailleurs ; choisir « Affectation automatique » rend la place au calcul. Changer de poste supprime son choix manuel. Les suggestions utilisent les mêmes critères de budget et de réputation que le diagnostic, réglés dans « Recrutement » > « Joueurs » ; leur coût et leurs notes restent indicatifs.
- Dans toutes les vues tactiques, les places suivent les postes enregistrés ou choisis dans la simulation : défense, pistons, milieu défensif, milieu et attaque occupent des lignes distinctes. Les postes axiaux restent au centre et les postes latéraux sur leur côté ; plusieurs places au même poste sont réparties sans se superposer. Le rôle choisi sert à l'évaluation et ne prédit pas les déplacements en match.
- Les terrains tactiques utilisent une présentation compacte commune inspirée du jeu, avec le code du poste et l'abréviation du rôle dans chaque rond ; le rôle complet apparaît au survol et dans les détails. L'extracteur actuel ne fournit pas les couleurs des maillots : dans « Données et outils du club » → « Couleurs de la tactique », choisissez et enregistrez les deux couleurs du club géré. Elles soulignent les places tactiques et sont retrouvées automatiquement lorsque ce même club est rechargé. Sans choix enregistré ou identifiant stable de club, l'affichage est neutre. Ce choix est local au navigateur, par club, et fait partie de l'export/import des données personnelles ; les couleurs et les maillots ne sont pas lus automatiquement depuis FM.
- **Historique de partie** : nommez votre partie dans le panneau latéral puis rechargez la base. À chaque chargement d'une nouvelle date, une capture des attributs de l'effectif et des cibles suivies est enregistrée automatiquement dans ce navigateur, par nom de partie et identifiant de club. Elle ne contient ni CA ni PA. L'historique conserve au plus 30 dates ; une capture à la même date remplace la précédente et une date plus ancienne est ignorée. Les identifiants absents ou ambigus sont exclus. Les entrées et sorties reflètent les données indexées, pas nécessairement des transferts : un joueur peut manquer de l'export. Le suivi des nouvelles cibles par filtres reste disponible dans « Alertes ».
- **Développement des jeunes** : les joueurs de l'effectif âgés de 21 ans ou moins affichent les variations d'attributs entre les deux dernières dates et les lignes de temps de jeu quand elles existent. Les lignes restent séparées : aucune ligne ne signifie pas zéro minute. Les performances FM27 sont expérimentales et les idées de prêt ou de vente sont à examiner, non des prédictions.
- **Confiance des données** : la vue d'analyse distingue valeurs exportées à confirmer, statistiques expérimentales, calculs indicatifs, données manquantes et comparaisons observées. Aucune valeur n'est certifiée exacte pour FM27 par sa seule présence dans l'export.
- **Navigation** : la recherche globale, accessible avec `/` hors d'un champ de saisie, cherche joueurs, membres du staff, clubs et postes ; `Échap` ferme ses résultats. Les colonnes des tableaux de recrutement peuvent être masquées individuellement et leur choix est conservé localement par partie et vue. L'extraction affiche le temps écoulé ; aucun pourcentage n'est annoncé puisque sa progression précise n'est pas disponible.

Les nouveaux historiques et préférences de colonnes sont inclus dans l'export/import des données personnelles. Ils restent soumis aux limites du stockage navigateur, notamment à sa capacité ; toute erreur d'enregistrement est signalée. Les scénarios mercato et tactiques ne sont pas sauvegardés et disparaissent lors d'un nouveau chargement. Après avoir mis à jour l'application, relancez le serveur et rechargez la page ; réextrayez la sauvegarde pour obtenir les statistiques de saison lorsqu'elles sont disponibles.

## Logos et visages

Les fichiers `config.xml` situés dans `Documents\Sports Interactive\Football Manager 27\graphics`, notamment les sous-dossiers du pack `Megapack TCM27`, associent les logos locaux aux identifiants FM des clubs, compétitions et nations. Les logos de club utilisent l'identifiant de base `unique_id`, distinct de l'identifiant interne à la sauvegarde. Les chemins relatifs des configurations sont résolus tant que le fichier correspondant reste dans le dossier graphique choisi ; les configurations XML avec espace de noms sont également prises en charge. Sans identifiant graphique ou image correspondante, l'application affiche un visuel de remplacement. L'index des logos est construit une seule fois à la première demande ; les demandes suivantes utilisent cet index en mémoire. Redémarrez le serveur après avoir modifié les packs.

Les fichiers `config.xml` des packs situés dans `graphics\faces` et ses sous-dossiers sont analysés au chargement de la page. L'application utilise les identifiants de personne des packs classiques, puis les noms uniques des packs de personnages générés ; les correspondances ambiguës sont ignorées. Les identifiants `r-` peuvent dépendre d'une autre sauvegarde et ne sont donc pas rapprochés directement d'un identifiant de personne. Les anciennes extractions sans `unique_id` doivent être relancées pour profiter de la recherche par identifiant. Une photo absente des packs locaux ne peut pas être affichée.

## Noms des pays et compétitions

Les pays sont identifiés à partir de leur identifiant de base FM, puis affichés en français. Si cet identifiant manque ou n'est pas reconnu, le pays est indiqué comme indisponible plutôt que deviné. Une nouvelle extraction peut être nécessaire pour les anciennes bases JSON qui ne contiennent pas `nation_uid`.

La sauvegarde n'inclut pas les noms des compétitions. L'application utilise les noms connus, les corrections en français présentes dans les fichiers `lnc` de l'installation Steam de FM27 et, s'il existe, le fichier personnel décrit ci-dessous. Elle ne peut pas retrouver les autres noms depuis la sauvegarde seule. Le classement disponible peut être celui d'une coupe plutôt que du championnat.

Pour compléter ou corriger les noms, utilisez le fichier facultatif `noms_competitions.csv`, encodé en UTF-8, avec l'identifiant **de base de données** de chaque compétition (et non son identifiant local à la sauvegarde). Dans la version depuis les sources, placez-le à côté de `server.py` ; dans la version installée, placez-le dans `%LOCALAPPDATA%\AssistantFM`. Si `ASSISTANT_FM_DATA_DIR` est défini, ce dossier est utilisé :

```csv
database_id,name
5123054,National League North
```

Les noms du fichier personnel priment sur les corrections installées et les noms enregistrés dans une ancienne extraction. Redémarrez le serveur et rechargez la page après modification ; une nouvelle extraction n'est pas nécessaire. Un CSV invalide produit une erreur au lieu d'être ignoré.

Le fichier personnel importé depuis « FM27 Fix by FMScout.lnc » reprend les noms indiqués par cette source, sans garantir qu'ils correspondent à la base ou à la saison de chaque partie. Notamment, l'identifiant 914523 y est appelé « Championnat National 1 Groupe C », alors que son logo local affiche N2 et que des références FM26 utilisent « National 2 Groupe C ». Vérifiez et corrigez le CSV si nécessaire. Ce fichier personnel n'est pas inclus dans la distribution de l'application.
